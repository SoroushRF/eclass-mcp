# v1.0.0-beta.3

Release date: 2026-05-20

## Summary

`v1.0.0-beta.3` is the Professional Engineering Maturity release for the eClass MCP engine. It keeps existing read-only tool behavior stable while adding `cache_health` and strengthening security boundaries, TypeScript discipline, protocol-level confidence, runtime cleanup, external-service resilience, trace correlation, cache observability, testability, and manual release validation.

## Highlights

- Hardened authenticated URL boundaries against unsafe schemes, spoofed eClass hosts, arbitrary authenticated navigation/fetch, private-network targets, and sensitive URL leakage.
- Eliminated production `as any` casts, tightened remaining production `any` annotations, and preserved typed MCP `registerTool` registration.
- Added MCP protocol integration tests using the SDK path to verify tool discovery, schemas, safe validation errors, and cache-tool protocol semantics.
- Centralized common eClass/SIS tool error and auth handling while preserving existing JSON response shapes.
- Added graceful shutdown cleanup for stdio, auth server/browser resources, eClass, Cengage, and SIS browser lifecycles.
- Added an RMP circuit breaker that returns structured `RATE_LIMITED` responses after repeated upstream failures.
- Added structured trace/span correlation on top of the existing Pino stderr logger.
- Added read-only cache observability with `cache_health`, cache metrics, pin/quota health, and redacted warning summaries.
- Added manual dependency injection for low-risk eClass, SIS, RMP, and Cengage tool tests.
- Refreshed the live/manual E2E release harness with a safe template generator and current 25-tool matrices.

## Upgrade Notes

- No public MCP tool names, schemas, auth flows, cache semantics, or scraper extraction behavior are intentionally changed in this release.
- `cache_health` is a new read-only local diagnostic tool; it reports aggregate cache/pin health and process-local cache metrics without exposing raw cache keys, filenames, URLs, cookies, or absolute local paths.
- Manual release validation now starts with `npm run e2e:template`; the generated template is a scaffold only and is not live evidence until filled by a human operator.
- Continue setting `ECLASS_MCP_SESSION_SECRET` before authenticating, as introduced in beta.2.

## Verification

Release prep expects these checks to pass before tagging:

```powershell
rg -n "\bas any\b" src
rg -n "server\.tool|:\s*any\b|\bany\[\]" src/index.ts
npm.cmd run typecheck
npm.cmd run typecheck:tests
npm.cmd run lint
npm.cmd run format:check
npm.cmd run test
npm.cmd run test:coverage
npm.cmd run build
npm.cmd pack --dry-run
git diff --check
npm.cmd run e2e:template
npm.cmd run e2e:template -- --phase "Task 10 Harness Smoke"
```

Manual Inspector / Claude Desktop rows in `docs/e2e-run-log.md` are not claimed as re-run for this release unless their Result and Evidence cells contain concrete live evidence.

## Known Limitations

- No write tool ships in this release. E20 preflight contracts are documented and implemented for future write tools; E21 post-write audit logging and cache invalidation remain pending before destructive tools should ship.
- WeBWorK remains pending.
- The RMP circuit breaker is in-memory and process-local, so it resets on server restart.
- Structured trace correlation is Pino/AsyncLocalStorage based; no OpenTelemetry exporter is included yet.
- Manual E2E evidence requires valid local credentials and host apps, and is intentionally not part of CI.
